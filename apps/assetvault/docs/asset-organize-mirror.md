### 当前代码交付范围（2026-11-15）

- V7 增加 `file_roots`、`file_locations`、`file_operations`；文件整理执行器使用持久日志记录准备、完成、撤销、取消和待恢复状态。
- 已入库且带有效 `localRoot/localRel` 的资产沿用原 UID，首次升级分批读取并在事务内认领位置；重复打开不重建定位身份。根默认只读，不按标签生成目录。
- 普通目录保存和 `asset:patch` 以已认领位置为准，旧页面不能将本地路径覆盖回旧值；经过现有内容校验的单文件重新定位通过专用内部接口更新位置。永久删除、替换导入同步清理定位记录。
- 「导入文件夹 → 整理文件」一次点击打开真实目录浏览器；文件夹名称直接进入，行内改名和移动入口直接可达，支持拖放到目标目录或上方路径。列表按 300 项分页，移动结果直接更新资产卡片和本地读视图，不依赖整页刷新。
- 各根默认只读，启用“允许整理源文件”前自动备份资产数据库并说明原件需要独立备份。移除根先撤销写权限。恢复未完成时暂停其它资产库 POST 写入口，面板保留历史和“重试恢复”。
- 同根 Windows 同卷移动使用 .NET File.Move / Directory.Move 的不替换语义，避免 Node rename 覆盖已有文件。按卷/文件 ID、大小、修改时间和目录清单检查源版本；目录子项定点更新位置和 URL，默认文件名跟随改名，自定义标题保留；收藏、标签和合集不重键。大小写改名通过已记录的临时位置中转。
- 旧位置若只有 SHA 摘要，首次整理会读取并核对内容；采用后记录卷/文件 ID 和创建时间，后续不重复哈希。缺少可靠摘要的旧资产暂时拒绝整理，不能只凭当前路径认领；已记录文件身份后，路径上换成另一个文件也会拦截。
- 撤销重复使用移动预检和日志；源版本变化、旧路径被占用时拒绝覆盖。文件系统成功而 DB 事务未提交时保留日志，重启或点击恢复时验证实际身份并继续提交；中转态可继续移动到目标。冲突或缺失不猜测、不删除原件，保留待恢复任务。当前失败主要采用身份核验后的继续完成策略，尚未实现所有错误下的自动反向回滚。
- “整理预检”保留为独立只读诊断。`/api/library/file-organize/preflight` 仍只读；`/api/library/file-organize/action` 提供目录、权限、预览、移动、历史、撤销、恢复和缓存管理，仅允许主机同源调用。
- 未入库的扫描卡片尚未迁移，不按路径重新分配这些卡片的收藏 UID。只有 `filePath` 的已入库历史记录可通过“导入文件夹 → 旧路径迁移”显式认领：执行前备份数据库，核对旧 SHA256，保留 UID、收藏、标签和合集，不移动源文件。缺少摘要、路径异常、同路径多个身份、链接或内容不符时拒绝认领，不自动合并资产。旧快照写入协议门禁已接入，扫描卡片旧关联迁移仍待完成。
- **当前可整理范围**：已登记根内的 Windows 普通文件或完整目录；目录中的所有普通文件必须已入库且位置唯一。未入库文件、链接/junction、Unity/UE 工程或 .meta、依赖型单文件、跨卷和覆盖操作会拦截；每次最多 2 万项 / 64 层。目标目录需已存在。此范围保证不会因为移动未认领的扫描卡片而静默丢失旧路径关联；不能据此宣称任意旧库已迁移完毕。带稳定资产记录的整根重新定位暂时明确拒绝，原有单文件重新定位仍可使用。
- 列表缩略图 GET、前端模型封面回传、服务端模型封面统一 384 px 规格，优先 WebP 质量 78，保留透明度、自动方向并移除无关元数据。缺少 sharp 时保留 PNG 兜底；底层显式 PNG/其它宽度接口保留给兼容调用，列表不跟卡片滑块生成变体。
- 缓存键改用可用的卷/文件 ID + 创建时间 + 修改版本 + 规格/编码版本，改路径复用；没有可靠文件 ID 时才回退路径。相同内容的独立副本尚不跨 inode 合并。新缓存文件名增加源身份分组和尺寸标识，内容 key 规则不变；旧 40 位命名命中后直接改名兼容，不重新编码。
- 缓存默认预算 5 GB，可在“导入文件夹 → 缩略图缓存”查看、修改、按预算清理或清空；预算配置保存在现有缓存根的 `budget.json`。超额回收到预算 90%，解码并发上限 4，同键请求合并，最近访问每 5 秒批量记账。清理只处理规定命名的普通缓存文件，拒绝缓存根链接且跳过条目链接/目录和生成中的键。
- V8 补充内置词条 `seed_key`、自动标签人工排除、逐资产/通道标注版本和持久补标任务。词表版本升至 4，共 407 个基础词条（原 346 个加平台分类去重扩充），涵盖软件、授权、来源平台、建筑室内、家具、植被、动物、人物服饰、道具、食物、地形、机械、风格、材质和用途等；格式、种类沿用已有结构化筛选，不重复生成实体标签。这是可扩充的基础词表，不宣称涵盖全部行业。
- 词条改名可显式保留 `id`：已有无显式 ID 的种子以首次规范名为 seed_key，改名时把该旧键写入 `id`，`term_id` 保持，旧名保留别名。重复 ID、改名碰撞及无效词表事务回滚且不推进词表版本；人工排除随旧别名词条合并迁移。此能力不等于完整的词条拆分/停用管理器。
- “导入文件夹 → 标签升级与补标”直接打开任务面板，支持开始/继续、暂停、刷新进度。按 100 个资产一批提交，已覆盖版本跳过，失败整批回滚，不错误推进资产覆盖版本；重启后用户点击继续，任务从未覆盖项恢复。文件整理有未恢复日志时补标暂停。关闭面板不终止正在运行的任务。
- 已有标签归一化通道 `taxonomy-existing-tags-v1`：只把已有原始标签确定性映射到当前有效词表，缺少关联时通过现有自动/AI 标签来源添加，不猜名称、图片内容、软件兼容性或授权，不调用付费 AI，不移动文件、不覆盖用户标签。删除自动/AI 标签建立同资产/词条/来源排除，补标和旧快照不再加回；显式添加可解除排除。“标签分类管理”中提供排除记录分页及逐项撤销，按记录时间校验过期请求；撤销仅允许下次补标重新判断，不立即加标签、不改变手动标签。
- V9 补充词条停用标记与编辑版本。“导入文件夹 → 标签分类管理”打开自定义词表管理，提供名称搜索和分页、新建、父级、多分类维度、改名、别名、停用/恢复、合并。行内主要操作直接可达；合并需指定目标并确认关联修改风险，执行前自动备份数据库。内置词条在此面板只读，可把自定义词条挂到内置词条下面；不重写内置 seed。
- 自定义标签改名保持 term_id，兼容保留旧名称和已有别名；资产的原始标签文本保留，不静默覆盖用户输入，搜索投影同步到新标准名。合并迁移来源关系、人工排除和子项父级，旧词条留 merged 重定向且旧名可检索；目标人工排除不会被源自动标签绕过。停用只从候选分面隐藏并阻止定点新增，已有历史关系和检索保留；恢复后可继续使用。普通整库兼容导入保留历史关系，不等同于强制清除停用词。
- 数据库筛选补充递归自定义父子展开，标签包含与排除均覆盖子孙；内置层级和旧子串回退保留。此能力针对已入库资产的服务端查询，不代表尚未入库扫描卡片或纯内存降级路径已拥有同等自定义词表语义。管理成功后本页的标签分面缓存失效，下次打开重新读取。
- 名称/别名冲突、无效父级、层级环和过期编辑版本拒绝并事务回滚。改名/合并目前最多影响 1 万资产，超过时拒绝并要求后台批量迁移；大库后台管理任务未实现。自定义词表变更使确定性补标进度失效并暂停旧任务，用户点击继续重新检查，现有资产标签不因此删除。
- 自定义标签行内提供“拆分子分类”：一次创建 2–20 个继承父分类维度的子项，执行前备份，名称冲突整批回滚。旧分类、资产归属及人工来源保留作为待细分；无确定规则时不自动分配资产。内置标签仍只读。V10 新增规则驱动的确定性细分：源父分类、目标直接子分类和已有标签精确匹配条件；同一父分类只在唯一目标命中时补充子分类，多目标歧义不分配。原有粗分类归属保留，不自动移除。
- 旧路径迁移按 rowid 每批 256 条读取全库核对路径冲突，最多审计 5 万条，超限明确标记不完整并禁止迁移；列表按 100 项分页，每次最多迁移本页 20 个可用项。逐资产事务提交，单项失败继续其它项；可停止 SHA256 读取，已提交项目保留。哈希期间占用数据库写队列，超大文件可能使其它写入等待。已完成下述合成元数据基准，尚未做真实全库迁移性能验收，不承诺全库无人值守迁移。
- 旧快照写入保护：启用真实目录整理或成功迁移旧路径时，在同一数据库事务内保存协议要求。`POST /api/library-state` 和 `POST /api/library/mutations` 在写队列内核验 `X-AV-File-Protocol: 1`，缺失或未知版本返回 426 和 `client_upgrade_required`，不执行保存。已整理过的旧库通过根写权限、操作日志或迁移审计识别；关闭权限或撤销操作不解除新标记。新版持久层自动携带标识，遇到协议拒绝停止后续保存并提示刷新，不整块重放。兼容的定点写继续沿用现有语义/位置覆盖保护；此标识是版本门禁，不是身份认证或任意同版本并发冲突检测。
- 数据库尚未创建的纯文件模式保留旧降级保存；已有数据库却无法读取时，快照写入返回 503 和 `write_protocol_unavailable`，避免在无法验证稳定位置的情况下落盘。当前保护针对 HTTP 旧快照通道，内部服务、显式备份恢复/整库替换不因此改为禁止；它们沿用各自校验与确认流程。
- “导入文件夹 → 缩略图缓存”新增直达“清理过期版本”，展示实际删除数量与释放空间。只对已入库且已定位、在线普通源文件核验当前身份和 key，删除同一源的过期尺寸/编码版本，保留当前不同尺寸与格式；离线源、未知身份、无法关联的旧命名缓存保留给预算 LRU。手动核验最多 5 万个源，超限不执行。预算清理先处理进程最近使用的最多 4096 个源的过期项，再执行 LRU，不在滚动请求中全盘对账。不会新增逐资产元数据文件，也不移动或删除原件。
- glTF / GLB 封面新增依赖版本：解析 `buffers/images` 的外部相对 URI，核验贴图和 .bin 的文件身份、大小及修改/状态时间；缺失与恢复也使下次封面请求失效。URI 清单只在模型版本未变时复用，最多缓存 256 份解析结果；每次仍检查依赖 stat，不读取全部贴图计算摘要。GLB 只读取头和首个 JSON 块，不读取整个 BIN；单份 JSON 清单最多 8 MB、外部引用最多 128 项；拒绝网络、越根、链接/junction 和异常引用，不访问任意外部资源。
- 前端 glTF / GLB 封面生成先获取 `/api/local/thumb/version`，依赖按完整相对目录加载并带版本参数，模型本体禁用浏览器缓存；回传携带 `coverVersion`，服务端核对后写入。渲染期间模型或依赖发生可观测变化时拒绝旧结果，前端任务按版本隔离，不再永久复用同路径的旧任务。过期清理携带登记根上下文核验依赖，支持根内上级相对引用。此能力不是实时文件监听；已显示封面需下一次请求/刷新后更新，依赖版本基于文件系统元数据，不保证识别刻意还原全部时间戳的内容篡改。有效 GLB 的外部依赖已纳入；不含有效 GLB 头的历史占位文件只保留旧封面回传兼容，不宣称完成解析。FBX、OBJ/MTL、Blend、USD 等依赖解析与真实浏览器渲染验收仍未完成。
- **仍未完成**：无法可靠归属的扫描卡片旧关联自动迁移、真实掉电/大规模文件占用验收、超过 1 万资产的后台词表改名/合并、按内容识别补标、非 glTF/GLB 的外部依赖解析、独立同内容文件的缩略图物理复用。未知关联只审计保留，不猜测修复。Billfish 适配已按用户要求本轮跳过，不作为当前开发阻塞项。
- 定向测试覆盖 V6 升级幂等、旧快照保护、标注/合集保留、真实临时目录移动/改名/大小写改名/撤销、失败注入后的重启恢复、外部占位不覆盖、HTTP 同源权限、晚到分页的位置修正，以及 WebP 透明/方向、改路径命中、并发合并、预算/LRU/安全清理。测试使用临时素材，不操作用户现有素材。50k/200k 合成基准见下文；尚无真实硬件断电或界面视觉验收数据。

### 本轮补充交付与验证

- V10 增加 `taxonomy_rules` 和规则修订号。标签分类管理面板直接添加/删除规则；标签升级面板直接切换三个补标通道：已有标签归一化、元数据与平台分类补标、规则细分分类。规则修改使对应进度失效并暂停旧任务，点击继续重新核对；删除规则保留已经产生的分类关联。
- 元数据通道只读取明确记录的 platform/originPlatform/importPlatform、software/softwares、license/licenses 字符串或数组，并核对目标词条维度。不从文件名、后缀猜软件或授权，不调用付费 AI。人工排除对三个通道统一生效。资产元数据修改后允许重新补标；词表修改使所有通道进度失效，补标自身写入只保留本通道进度。
- 三通道均复用每批 100 项事务、失败回滚、暂停和重启续跑。补标只追加有依据的关联，不自动撤销旧元数据或旧规则曾产生的标签；需要撤销时通过标签管理操作。覆盖数表示已检查，不表示每个资产都有新增标签。通用整库导入不携带本机细分规则；replace 保留本机词表及规则，清除旧资产补标进度，避免导入后误用旧覆盖状态。
- “旧路径迁移 → 全库关联审计”直接执行只读报告，列出未知收藏、手动/自动标签、备注和合集关联，以及旧快照重复 UID、资产 payload 身份异常。报告保留未知关联，最多展示 100 项；它不是自动迁移或修复按钮。
- 主要操作路径保持直接可达：导入文件夹面板一次点击打开整理、补标、分类管理或缓存管理；各面板的切换/开始/暂停/添加/删除按钮直接操作。旧路径迁移面板中一次点击执行全库审计。没有新增“更多 → 管理”中间层；移动原件权限和不可逆合并的确认用于保护数据。

### ArtStation / Sketchfab 分类接入（词表 v4）

- 分类目录复用已保存的 ArtStation 59 类和 Sketchfab 18 类，定义与标准词映射集中在 `server/platform-categories.mjs`。对应平台名称、原始 ID、slug、名称存入资产 payload 的 `platformCategories`，兼容的 `categories` 名称列表继续保留；未知分类和只有 ID 的记录不丢弃。
- 依据明确含义分别纳入题材、风格、用途、技术维度。标准词/别名已存在时复用旧词条，不新建重复身份；缺少的使用稳定 seed ID，词表合计 407 条。组合分类保持完整含义，不把“角色与生物”强行拆成两个同时成立的标签；不使用在线搜索树的近似范围给资产打标。
- ArtStation 搜索与作者列表保存作品返回的 categories/category_ids；已有官方筛选清单时可解析 ID 对应名称。详情链接解析和图片/模型下载来源信息保留原始分类。Sketchfab 搜索结果保存原始分类 ID、slug 和名称，不再只留下名称字符串。
- 旧资产通过“标签升级与补标 → 元数据与平台分类补标 → 开始 / 继续补标”处理；平台分类复用既有元数据通道；新增文件信息匹配后共四个通道，没有新增隐藏入口。只有已存储且能明确识别的平台分类才补标，不联网批量补抓作品，不从搜索参数、文件名推断。旧 ArtStation 资产原分类为空时无法凭空恢复，需要后续重新获取作品元数据。
- 标准关联复用现有自动标签来源，并记录元数据补标通道；原平台分类保留在资产 payload，不覆盖平台原始 tags，也不替换手动标签。人工排除、暂停续跑和失败回滚沿用已有逻辑。词表 v4 使 v3 已覆盖资产允许重新检查，补标不移动本地文件。

### 非视觉文件信息分析

新增通道 `taxonomy-file-text-v1`，入口为“导入文件夹 → 标签升级与补标 → 文件信息匹配（无需视觉）→ 开始 / 继续补标”。通道按钮直接可点，不进入更多菜单；当前共四个补标通道。用户显式启动后处理已入库的有效资产，关闭面板不停止，可暂停、重启后继续。

- 读取已保存的名称、标题、sourceRel/localRel 相对目录、描述、摘要、关键词和 subject。缺少相对路径时只使用 filePath 的文件名，不把盘符、用户名和绝对根目录当分类。路径最多末尾 32 段，每个字段最多 16,000 字符；不扫描磁盘、不读取图片像素、不联网、不调用 AI、OCR 或 CLIP。
- 匹配有效词表的标准名和别名，包括自定义标签；结果只归入既有词条，不自动制造新词。统一全半角、大小写、下划线、连字符和空格，英文按完整词边界，中文词组按连续文本匹配，同起点优先长词。跳过一字词及少于三个字符的纯非中文词，归一后有歧义的词组不分配。
- 用词表前缀索引匹配文本，同一词表索引在批次之间复用，词表/别名/维度变化后重建；每批仍为 100 项事务。无需对每个文件重新扫描全部词表。该优化不代表完成几万张真实素材的性能验收。
- 不根据文件名或描述推断授权、软件兼容性、平台来源，对包含这些维度的词条整体跳过；这类信息仍走明确元数据通道。格式、种类、尺寸等继续由已有结构化字段承担，不重复造标签。
- 生成结果存为自动标签，来源记录为本通道；人工标签保留，已有自动标签排除生效。已有名称/元数据修改会使进度失效，应用内目录移动/改名清除对应文本匹配覆盖，下一次点击继续重新核对。仅追加匹配项，旧名称/目录曾产生的自动标签不会自行删除。
- 这是词语命中，不是内容理解：不能判断否定句、描述是否准确、图片实际是什么；无信息的随机文件名可能没有任何匹配，不算任务失败。没有读取文件内嵌 EXIF/XMP/IPTC，未提供语义搜索或图片内容识别。匹配后可通过现有自动标签删除/排除进行纠正。

合成基准报告：[asset-organize-scale-results.json](asset-organize-scale-results.json)，运行命令 `node scripts/bench-organize-scale.mjs --output docs/asset-organize-scale-results.json`。Node 22.19.0 / Windows / Intel Core Ultra 7 265KF，单次测量：

仅测合成 SQLite 元数据核心，不代表真实导入、图片解码、批量搬文件、硬件断电或界面流畅度验收。20 万条下的标签筛选和整根预检仍有明显成本，保持显式按需执行，不放入高频滚动路径。fixture 插入时间不等于生产导入耗时。

## 1. 目标与唯一原则

用户在 Arvimo 整理真实文件夹时，电脑上的源文件夹同步移动、改名；分类由统一标签系统承担。
文件夹管位置，标签管分类，两者独立。无需维护原始区和整理区两套文件树。

- 文件夹节点对应已登记根内的真实目录，移动和改名同时更新文件系统及数据库定位信息。
- 格式、种类、内容、风格、来源平台、适用软件、授权等均为标签维度，不自动映射成目录。
- 合集、智能合集是虚拟集合，加入或退出合集不移动文件，亦不再引入 primaryCollection。
- 不新建 organized/、organized_links 或硬链接镜像，不按标签自动搬文件。
- 原件可直接被资源管理器及其他软件访问；标签、身份与关联集中存数据库，不要求每文件附加 JSON。

## 2. 磁盘结构与操作结果

文件根和应用数据根分开登记，允许在不同磁盘；数据库不强制放在素材目录。

```text
H:/素材/                         已登记的真实整理根
  场景/
    森林素材包/
      tree.fbx
      textures/bark.png
  角色/
  待整理/                        导入时的默认落点，可直接选择其他目的地

<应用数据根>/
  library.db                     身份、位置、标签、合集、操作记录
  <现有缓存目录>/                 可重建缩略图等，沿用已有配置
```

| 用户操作 | 文件系统 | 数据库 |
|---|---|---|
| 文件夹中移动文件、素材包或目录 | 实际移动 | 更新位置及目录内所有已登记子项 |
| 文件夹改名 | 实际改名 | 同步更新子项位置，资产 ID 不变 |
| 添加、移除标签 | 不变 | 更新标签关联 |
| 标签改名、移动父级 | 不变 | 更新词表及筛选关系 |
| 加入普通合集、调整合集层级 | 不变 | 更新虚拟集合 |
| 移到回收站 | 使用可恢复的应用回收机制 | 保留身份、标签、原位置和恢复信息 |

目录名只表示用户实际选定的位置，不由格式、种类或来源自动重写。素材包内部结构默认完整保留。

## 3. 身份、路径与数据库

### 3.1 稳定资产身份

复用现有 UID 和身份兼容方案，不以路径或内容哈希直接替换全部 UID。
目录移动、改名、根目录重新定位都不改变资产身份；标签、收藏、评分、合集与资产身份关联。
同内容的两份文件不自动合并逻辑资产，不擅自物理去重或删除。

沿用 `local-asset-identity-design.md` 的 FileLocation 方向：

- 位置：asset_uid、location_id、root_id、rel、mode、availability、fingerprint_version。
- 根：稳定 root_id、当前绝对路径、是否允许真实整理；relink 只改定位，不换 root_id。
- 文件特征：大小、修改时间、可用时的卷 / 文件标识，已有可靠摘要可复用；不靠同名认同一文件。
- UI 显示绝对路径，库内定位优先 root_id + 相对路径；不要求每次操作重新哈希大型文件。
- 未登记文件首次受管理前建立身份；旧路径键通过明确 alias 迁移，未知关联保留待处理。

标签词表、资产标签关联、文件位置、迁移历史均进入 library.db；复用现有表并追加兼容迁移，
禁止再造第二套标签数据库。资产包内容清单与依赖关系按实际资产粒度登记，不强制把每张配套贴图当独立资产。

### 3.2 真实整理授权边界

外部目录默认仅索引。用户启用该根的「允许整理源文件」后，才允许真实移动、改名。
在文件夹面板明确显示真实路径及可写状态；只读根仍可标注、搜索。
普通已授权的同卷移动无需反复确认；覆盖、跨卷删除源件或已知外部引用风险需明确提示。
不追踪 junction / 符号链接越出授权根，不允许循环移动、越界路径或移入自己的子目录。

## 4. 文件移动与一致性

文件系统和 SQLite 不能组成一个原子事务，必须使用持久操作记录及可恢复状态机。

1. 预检：校验源身份、可写根、目标路径、重名、依赖包边界及受影响记录；目标冲突禁止覆盖。
2. 写入操作计划和恢复信息，记录旧位置、目标位置、操作 ID；相关源和目标范围加锁，重叠任务串行。
3. 首期只支持同卷真实移动。优先使用系统 rename；大小写改名如需临时中转，也必须记录中间态。
4. 文件系统成功后，在 DB 事务中更新所有受影响位置和任务状态；发布一次定向刷新通知。
5. DB 失败时尝试安全回退；源目标被外部更改或占用导致不能回退时，保留恢复任务和真实结果，
   阻断冲突操作并提示处理，不宣称成功，也不把文件当作失踪后删掉。
6. 重启检查未完成任务，根据已记录的身份和实际位置继续或恢复；不可凭文件名猜测。

移动完成后不用等待下一次全库扫描才能看到新路径。扫描器应识别应用操作，避免当成删除加导入。
撤销使用同样的预检、日志和身份验证；旧路径被占用时停止并报告，不覆盖新文件。
目录整体操作避免逐文件复制；大量子项的 DB 更新在后台分批处理，任务期间对相关范围保持一致性保护。

跨卷移动首期明确拒绝并说明原因，不能静默转成复制删除。后续如支持，必须另行实现：
空间预检、可中断复制、内容校验、目标提交、删除源件的安全恢复与进度；完整校验前绝不删除源件。

### 4.1 名称、素材包与外部引用

- Windows 名称校验覆盖保留名、非法字符、尾随空格 / 点、大小写冲突及长路径；禁止 ../ 越界。
- 重名提供独立命名或取消，原名保留在来源记录；自动命名需稳定且不得覆盖。
- 模型、贴图、MTL、配置等默认按素材包整体移动，保持相对目录；不承诺自动修复包外绝对引用。
- Unity / UE 项目目录首期不开放通用真实整理；需使用相应软件的资产移动接口才能维持其引用。
  Blender 等已知工程引用风险显示提示；未发现引用不等于保证无人引用。
- 文件夹直接拖动到目标即可移动，改名有独立入口；长任务可查看进度和结果，不要求先打开管理页。

### 4.2 资源管理器中的外部修改

首期不承诺外部移动或改名自动识别。检测到缺失仅标记不可用，保留 ID 和全部人工数据，提供重新定位。
重新定位时校验身份与歧义，不能把旧路径中新出现的不同文件自动套用旧标签。
后续 watcher 只能作为提示来源，需配合恢复扫描；不能把所有 delete + create 都认成 rename。
外部覆盖、重复导入、文件标识复用和跨卷移动均需有冲突处理，不可仅凭 mtime / size 自动确认。

## 5. 统一标签词表

### 5.1 内置维度

| 维度 | 示例 | 默认标注来源 |
|---|---|---|
| 文件格式 | PNG、PSD、FBX、BLEND | 文件探测，改扩展名不等于转格式 |
| 资产种类 | 图片、模型、材质、音频、字体、素材包 | 探测 + 人工纠正 |
| 内容分类 | 植物 → 树木 / 多肉；建筑 → 住宅 | 规则、人工或按需 AI |
| 风格 | 写实、卡通、低多边形、手绘 | 人工或按需 AI |
| 来源平台 | Sketchfab、Fab、Billfish | 导入来源记录 |
| 适用软件 | Blender、Unity、UE | 有依据的兼容信息或人工标注 |
| 授权 | CC0、CC-BY、商业授权、未知 | 来源证据或人工确认，不能靠 AI 猜授权 |
| 自定义 | 项目、用途、个人整理标签 | 用户 |

维度支持层级和多选。筛选规则：同维度默认 OR，不同维度默认 AND；排除筛选另设明确入口。
选择父分类默认包含后代，不必给每个资产永久写入所有父标签。
格式、种类和来源分别表达不同含义，不能互相代替；导入渠道 Billfish 与原始来源 Sketchfab 可同时保留。

### 5.2 词条与自定义

复用 `library-vocab.mjs`、`library-vocab.seed.mjs`、`vocab-sync.mjs` 和现有标签写入通道。
在现有 term_id / facets / aliases / parent 能力上补足缺项，不新建平行词表系统。

- 每个词条有稳定 ID、维度、显示名、别名、父级、系统 / 用户归属、启用状态和版本信息。
- 同维度规范化检查空格、全半角和大小写；不同维度可出现同名，不用名称作持久关联键。
- 父级不能成环；别名冲突必须报告，不能任意选择归属；本地化显示名不改变 ID。
- 用户可新增自由标签，也可在内容等可扩展维度添加子分类，不能全挤入「其他」。
- 在受控选择器中直接搜索、选择或创建；检测同义候选并提示复用，普通选择立即生效。
- 内置词条停用不硬删除历史关联；升级不能覆盖人工显示名覆盖值、自建子项或个人标签。

### 5.3 标签关联来源与覆盖规则

词条归属和标注来源是两件事：系统词条也可由用户手动标注。
关联至少记录 asset_uid、term_id、source、规则 / 模型版本、时间，必要时记录置信度与证据。

- 区分用户、平台、规则、AI 来源，单个词条允许多个来源支持；UI 合并展示但不丢来源。
- 自动任务只能更新自身产生的关联，不能删用户标注、平台事实或其他来源的关联。
- 用户否定自动标签时保存排除记录，后续任务尊重该决定，不反复加回；用户可撤销排除。
- 人工确认、纠正和自动建议分开；低置信度结果进入待确认，不伪装成已确认分类。
- 来源变更、合并和撤销有审计记录；更改标签绝不触发物理文件移动。

## 6. 词表持续扩充与旧资产更新

分别记录词表版本、规则版本，以及资产在各标注通道的完成版本 / 状态；不能只用一个全局已完成数字。
新增分类不会凭空知道旧资产是否属于该类，必须经匹配或确认。

| 变更 | 旧资产处理 |
|---|---|
| 改名、增加别名 | ID 不变；展示及查询更新，无需重识别文件 |
| 调整父级 | 更新树和筛选索引；不搬文件、不批量添加父标签 |
| 合并词条 | 指定保留 ID，迁移关联并去重；旧 ID 重定向，保留来源及人工排除 |
| 新增分类 / 修改规则 | 计算受影响候选，按需要补标，新增项不默认套到全部资产 |
| 拆分分类 | 保留旧归属为待细分；规则可确定的迁移，歧义项待确认，不随机分配 |
| 停用词条 | 保留历史关联和可追溯信息，允许迁移，不直接丢数据 |

后台增量任务记录版本、范围、游标、成功 / 失败数和错误原因；幂等、可暂停、可恢复、可重试。
只有实际成功完成的资产 / 通道才能推进版本；缺失文件与失败项保留待处理状态。
任务读取时记录资产修订号，提交时检查并发人工修改；冲突重新计算，不写回过期结果。
大库先用已有元数据缩小候选，必要时分批扫描；覆盖正确性优先，不能漏掉没有旧标签的新候选。
文件解析和 AI 只在需要时运行，AI 更新为可选能力，不自动消耗付费额度。
纯词表更新不重建全部缩略图；可见 UI 只接收必要增量，不能每处理一条就重绘全库。

## 7. 导入与 Billfish 兼容

支持两种明确入口：复制导入到整理根、索引现有目录。默认不移动或修改外部原库。
复制导入可以直接选目标真实目录，或进入「待整理」；不强制按日期拆散同一素材包。
索引外部目录后，可独立启用该根的真实整理权限。

Billfish 适配按用户最新要求本轮跳过。未来恢复时复用现有导入机制，新增适配前用实际样包核实格式。
当前不能据本设计宣称支持所有 Billfish 版本、加密资源库或私有封装。

- 解析、验证、预览文件数 / 大小 / 元数据 / 冲突，再复制原件到目标根；来源包保持不变。
- 保留素材包依赖与内部相对目录；压缩包展开防止路径穿越、链接逃逸及异常展开体积。
- 来源目录可还原为真实子目录，来源的多归属分类导入成标签或虚拟合集，不复制多份原件。
- 标签与内置词表可确定映射的复用；未知词条按来源或用户扩展保存，禁止静默丢弃。
- 以来源库稳定身份 + 来源资产 ID 记录幂等关系；缺少稳定信息时提示重复候选，不靠包绝对路径生成永久身份。
- 内容相同不等于可自动合并。导入预检、取消、失败恢复和重试不得造成半成品资产或丢原件。

## 8. 缩略图压缩与缓存

复用现有缩略图服务和缓存位置，不在源文件旁生成副本，不要求每个依赖文件单独有封面。

- 列表封面最长边 **384 px**，保持比例、不放大小图；建议 **WebP 质量 78**，抽样后可在 75–80 调整。
- 保留透明度，先处理方向和色彩再移除 EXIF / GPS 等无关元数据；文字、透明边缘及模型封面分别抽样。
- 每张几十 KB 是目标而非保证；不为了硬性字节数无限降质或反复编码。
- 仅可见和邻近项按需生成，有界并发；高清预览打开时再加载，不导入即全库编码。
- 卡片尺寸滑块只改变显示尺寸，列表复用固定规格，不逐像素、逐 DPR 产生缓存变体。
- 缓存键含稳定源身份、源版本、封面参数和编码版本；同内容且参数一致可复用，移动改名不重复生成。
- 相关贴图等依赖变更参与失效；同键并发任务合并，临时文件加原子替换发布，失败不留半成品。
- 预算建议默认 **5 GB**，允许调整，10 GB 作为大库选项；预览、转码中间产物若另占额度必须单独显示。
- 超额先清过期版本，再按最近最少使用淘汰到预算 90%；使用中条目保护，结束后继续收敛。
- 最近访问批量记账；目录对账在后台分批进行，不在滚动事件中遍历缓存或同步写 DB。
- 缓存管理直接展示占用及预算，提供「清理过期」「清空缩略图」；清理不碰源文件、标签和目录。
- 清理验证应用缓存根，拒绝符号链接 / junction 越界；缓存可重建，不作为必要备份内容。

## 9. 备份、兼容与迁移

- 必须同时备份源文件根和数据库，保存 root_id 与对应关系；缓存可排除。不能把复制原件称为完整标签备份。
- 导出独立文件默认不携带数据库标签；需要可移植元数据时，提供显式导出清单，不强制每文件附加数据文件。
- 文件操作任务进行中，备份应等待一致性检查点；SQLite 用现有一致性备份能力，不直接随意复制活动 DB。
- 当前身份、扫描、收藏、标签、合集、搜索、回收态、缓存及所有导出调用方需做关联迁移。
- 复用现有 DB 合并 upsert 和定点写通道，不再假定每次 save 清空 assets；性能指标以实际基准为准。
- 上线前先预检旧数据、备份并生成幂等迁移计划；未知旧关联保留待解析，不全库重键、不丢记录。
- 如用户实际已有旧 organized 硬链接目录，不自动删除或把它当新原件重复导入；单独核实身份后处理。
- 不同时开放旧客户端快照写入新整理协议；已在快照/旧增量入口加入版本门禁，兼容定点写依赖稳定位置覆盖规则。仍需完整旧关联迁移和真实多客户端验收。

## 10. 分阶段交付与验收

| 阶段 | 内容 | 必须验收 |
|---|---|---|
| P1 | 稳定身份、根和位置兼容迁移 | 改名后身份不变；旧收藏 / 标签 / 合集保持；重复 UID 和未知关联可见 |
| P2 | 真实目录同卷移动、改名、撤销与恢复 | 文件与 DB 一致；目录后代一起更新；占用、重名、越界、大小写改名、掉电重启覆盖 |
| P3 | 内置分维度词表、自定义与来源隔离 | 层级查询、别名冲突、人工纠正、排除、合并与停用不丢数据；不产生物理搬迁 |
| P4 | 词表升级与旧资产后台增量补标 | 新增 / 拆分规则正确；暂停续跑幂等；并发人工编辑保留；失败不错误推进版本 |
| P5 | Billfish 样包预检及兼容导入 | 实测支持格式有清单；来源不动；依赖完整；重复导入不静默复制或丢标签 |
| P6 | 缩略图压缩、复用与容量治理 | 透明 / 方向 / 色彩正确；调尺寸、改路径不新增变体；超额淘汰、清空后重建正常 |

阶段按现有能力补缺，不重复重写已实现模块。P1 / P2 的安全验收通过前，不开放真实库批量移动。
验收在临时资产夹具中完成，不拿用户真实素材验证删除或回滚；真实迁移需有明确范围和可恢复备份。

性能验收记录资产数、文件数、目录深度、机器、介质、耗时与峰值内存；文件容量与资产条数分开统计。
覆盖 1k / 50k / 200k 元数据规模，移动只更新受影响位置，自动补标可恢复；不预填没有测量依据的秒数。
缓存记录平均 / P95 字节数与生成耗时；交互无全库同步扫描、重复保存或逐项全屏渲染。
