### 兼容与生效说明

- 新增 `canvas_sync_version` 表与 12 个触发器，版本由随机 epoch 加事务递增序号组成；旧服务可忽略附加表，既有表写入仍会触发版本更新。运行中恢复无此表的旧备份时自动重建并更换 epoch，避免复用恢复前的验证器。
- 本地图集可能受磁盘变动影响，存在图集时继续扫描合并，不强行走空闲 304。并发写入跨越读取事务时使用临时验证器，下轮重新取文档，避免把旧文档标为新版本。
- 回退仅撤销对应代码，不恢复旧数据库覆盖用户新修改；附加表可保留。真实运行中的后台需要重启才能加载服务端变更，本轮构建不表示生产实例已经生效或验收。

## 1. 目标与范围

在保留现有功能、数据语义和操作入口的前提下，减少启动读取、画布同步、重复请求及无效绘制。覆盖资产库、嵌入画布、下载状态协作和二者之间的导航交互。

不以隐藏按钮、增加菜单层级、减少同步能力、裁剪用户数据、降低预览质量或禁用后台任务换取性能。本文不包含平台采集改造、界面换肤或整体重写。

主要操作路径维持：

| 操作 | 验收路径 |
| --- | --- |
| 进入资产库 / 画布 | 点击侧栏对应入口，一次点击 |
| 切换画板 | 点击已有画板入口直接进入，保留原选择器路径 |
| 收藏、标签编辑 | 保留当前直接入口，普通操作不增加确认 |
| 拖入画布 / 加入画板 | 沿用现有拖放及加入入口，不增加中转步骤 |
| 下载刷新、重试、取消 | 沿用当前按钮和真实状态，不等待下一次轮询才反馈 |

- 资产库：空库、约千条真实规模副本、1万条合成库；更大边界仅在前述样本不能解释趋势时追加。

- 请求场景：单窗口、双窗口、连续切路由、服务短暂断连和恢复。
- 记录启动请求/响应体积、首屏可操作耗时、目录读取条数、空闲60秒同步流量、文档序列化/还原次数、重复请求数及局部操作DOM变更量。

## 4. 阶段1：资产库分页读取真正减量

### 方案

在数据库权威可用时，分页启动分支只读取必要的非目录状态、回收站与有效资产数量；有效资产由现有 catalog/page 返回。保留不带分页参数的旧读视图。

1. 检查 ensureIndex / authoritative / mergeDomains 是否仍隐含全量目录工作，不能只将最后的 models=[] 前移后宣称完成。
2. 优先复用现有 DB 查询能力；确需补充时增加最小的回收站读取、计数接口，不新建存储抽象。
3. 首批封面恢复按当前分页条目处理；恢复结果必须按 uid 合并，不改变原图、来源或下载定位信息。
4. 下载恢复条目的 recovered 语义必须保留，不因分页而漏发、重复登记或复活已删除资产。
5. DB不可用、旧服务不支持分页时沿用现有兼容路径，明确区分快照与权威数据。

### 验收

- 分页启动不调用完整有效目录读取；首批目录数量受请求上限约束。
- 回收站、收藏、评分、标签、备注、历史与设置完整；全量旧读视图保持原契约。
- 补页期间的收藏/标签/删除/导入不会误删未加载条目、覆盖新数据或复活旧资产。
- 缺封面恢复、重复 uid、空库、DB故障、文件模式和旧服务兼容均通过。

参考测试：`library-catalog-paged.test.js`、`library-catalog-read.test.js`、`library-catalog-slim.test.js`、`library-storage-db.test.js`、`library-persistent-storage.test.js`；按实际改动选择，不机械全跑。

## 5. 阶段2：画布版本校验与条件读取

### 方案

为 `/api/library/artflow-board` 增加文档版本验证器，沿用现有GET/PUT主体结构与同源权限。建议使用 ETag + If-None-Match + 304，避免为同一文档另建轮询端点。

- 首次 GET 仍返回完整文档；未变化时返回304且不调用 response.json()，变化才返回全文并执行必要还原。
- 版本必须覆盖画布保存、库侧画板成员变化、删除/重命名、reconcile产生的变更、导入/恢复和服务重启。检查全部写入调用方后选择事务版本或稳定内容摘要。
- 同一毫秒不能出现漏变更；重启后不得误命中旧验证器。禁止仅用 Date.now() 或文件mtime作为唯一版本依据。
- 若用摘要，不在每次轮询前重新读完整文档并全量 stringify；摘要/版本应在实际提交处生成、复用。
- GET 当前可能触发reconcile：条件判断前必须正确处理库侧变更。仅减少响应体而仍全量reconcile不算完成服务端性能目标。
- PUT保留 `{document, base}` 合并语义及原响应；版本是读取优化，不替代多人冲突处理。不能直接采用“最后写入覆盖”。
- dirty、busy、generation、canvasBaseline、保存等待者、本地副本回退及断连重试规则不变。GET返回后再次检查本地是否变脏。
- 304只能在持有对应文档基准时使用；基准丢失、服务器不支持验证器或旧客户端均能安全回退完整读取。
- 保留既有3秒变化发现节奏、focus与画板事件补拉；有脏数据时正常保存，不能为了减请求暂停待保存内容。

### 验收

- 空闲轮询多数为304，没有重复全文下载、比较、还原；有变更仍及时同步。
- 两窗口同时改不同节点、库侧改成员、重命名/删画板均保持现有合并结果。
- 远程响应迟到、本地编辑中、保存中、断网恢复、重启和旧服务兼容不丢修改。
- 撤销/重做、相机移动、空画板、媒体引用与缺失素材保留原行为。

参考测试：`library-canvas-boards.test.js`、`library-board-contract.test.js`、`library-board-navigation.test.js`；给实际变更与竞态补必要回归。

## 6. 阶段3：画布进入与刷新合并

将同一轮 enterCanvas 的初始化合并为一个共享 Promise，成功后复用同一iframe和桥接对象；失败必须清理该Promise以允许重试。

- 查全侧栏、open-canvas-board、设置ensureCanvas等调用方，调用结果可等待且只挂载一次。
- 初始化过程中请求打开不同画板，以最后一次明确导航意图为准；不能因合并请求丢失目标画板。
- 同时发生的refresh复用在途请求，完成后依据dirty状态与后续刷新意图处理；不静默丢弃待保存变更。
- 切出画布保留当前文档、相机和撤销栈；销毁时清理事件与定时器，不借本轮改造成“每次切换重建”。

验收：快速连点画布、立即打开指定画板、失败再试、切出再返回，只出现一个iframe与一组监听，最终画板正确；正常操作不多一步点击。

## 7. 阶段4：下载状态共享与扫描去重

先确认两处轮询是否重复取相同快照，再让 app.js 的图片任务监测复用 download-ui.refresh / onUpdate 数据。保留已有 ETag、pending Promise和轮询节奏，不引入全局事件框架。

- “未变化304”也要正确维持连接状态与需要的本地任务计时，不误判断连。
- 图片任务首张落盘、完成、失败、重试、取消、暂停、目录失效等状态不能遗漏。
- 同一批任务变化触发的扫描合并；手动强制扫描若发生在普通扫描中，必须随后落实强制扫描意图。
- 网络请求失败不清空已有任务；不把同一快照重复合并、重复提示或重复落盘。
- 当前活跃下载可见页更新频率不能明显降低，后台节流及恢复可见时补刷保留。

验收：同一时刻快照请求不重复，任务状态和新文件出现时间不退化，下载页所有按钮及文件定位正常。

参考测试：`library-downloads-snapshot.test.js`、`library-download-card.test.js`、`library-download-recovery.test.js`，以及改动涉及的扫描测试。

## 8. 阶段5：局部交互更新

先测 renderGrid 是否真的重建节点。对只改变当前卡片显示且不影响当前结果集合、排序和计数的操作，复用现有卡片更新函数；不改变状态真值或持久化路径。

| 操作场景 | 处理原则 |
| --- | --- |
| 普通列表收藏切换 | 可局部更新爱心及相关计数 |
| 收藏筛选内取消收藏 | 必须从当前列表移除并补位，不能只改爱心 |
| 改标签/评分影响当前筛选或排序 | 正常重新计算列表，保留必要重绘 |
| 批量修改 | 先保存统一状态，再合并一次界面更新 |
| 修改失败 | 恢复原显示或显示明确失败，不能假成功 |

局部更新保留键盘焦点、滚动位置、选择高亮、预览详情、右键入口与拖放绑定。禁止复制第二套卡片HTML、在DOM里保留与state冲突的状态。

参考测试：`library-favorite-targets.test.js`、`library-paging.test.js`、直接受影响的标签/评分测试；无对应行为不硬凑实现镜像测试。

## 9. 内置浏览器交互验收矩阵

| 流程 | 必须保持 |
| --- | --- |
| 资产库滚动后进画布再返回 | 当前筛选、已展示窗口与合理滚动位置；不无故跳顶 |
| 多选后切页/筛选 | 先记录当前产品规则，按原规则保留或清除；本轮不擅改语义 |
| 拖资产到画布、拖外部文件 | 导入反馈可见，去重与素材引用正确，不重复节点 |
| 拖动、缩放、框选、分组 | 操作结束正常保存；撤销/重做可回到正确状态 |
| 输入文字/编辑标签时按快捷键 | 不触发宿主删除、搜索或画布快捷键冲突 |
| 保存中切画板/离开/刷新 | 已提交状态可靠；待保存状态按既有规则处理，不假报成功 |
| 网络失败与恢复 | 保留旧内容，能重试；不自动清库或回滚到陈旧副本 |
| 双窗口协作 | 不覆盖另一窗口的有效修改；状态最终一致 |

先用隔离服务与数据副本验证，再按需要进行真实实例只读冒烟。登录由用户完成，不复用未授权凭据；构建同步不等于运行中的服务已加载新代码。

## 10. 交付、停止与回退

顺序：基线 → 分页减量 → 画布条件读取 → 进入去重 → 下载协作 → 局部更新。每阶段独立可检查，前阶段验收后再进入下一阶段，不一口气跨域重写。

每阶段交付：改动文件、必要检查结果、前后同样本指标、实际浏览器结果、未覆盖项。没测到的性能收益只写预期，不能写固定百分比或“全部提速”。

功能回归、数据丢失/复活、同步遗漏、焦点/多选/滚动行为退化优先处理；若优化无可测收益，停止扩大范围。连续修复失败按项目规则重新定位，不反复盲测。

回退以本阶段最小代码变更为单位，保留其它工作区修改。数据库如需增加版本字段，必须向后兼容并明确旧服务读写行为；禁止通过恢复旧数据库覆盖用户的新修改。不预设新全局开关或依赖。

完成条件：所有已实施阶段满足对应功能验收，必要检查通过，性能数据能说明减少了哪些工作，且无相关未解决风险；未实施阶段明确标为待开发。
