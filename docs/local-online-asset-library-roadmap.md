# AssetVault 本地＋在线资产库开发方案

> 日期：2026-11-12  
> 状态：开发规划，待逐项实施；本文件不代表功能已经修复或完成。  
> 对标：本机 AssetVault 当前工作区与 Serpent 0.3.4 当前源码。  
> 目标：保留在线素材发现、授权下载与 3D 工作流优势，建立可信、可恢复、可同步的本地资产底座。

## 1. 范围与事实口径

本方案基于只读源码审查、现有专项单测与临时库诊断。审查期间没有修改业务代码、用户库、原始素材或在线账号状态，没有启动浏览器、构建或执行全量测试。

证据分级：

- **已复现**：在系统临时目录创建隔离库，通过真实存储 API 触发并观察结果。
- **静态确认**：已追踪相关源码调用链，但未在真实网络或宿主环境执行该异常流程。
- **规划**：建议能力或目标设计，不能视为现有功能。

代码行号为本次审查时的位置，后续变动后应按函数名重新定位。工作区存在大量预先修改与新功能，实施时必须保留，不得重置或覆盖。

### 1.1 当前已有能力

AssetVault 已具备在线来源聚合、下载队列、本地目录导入与扫描监听、多库、合集、备份恢复、Eagle 兼容导入、整库 JSON 导入导出、WebDAV 快照交换、文本向量检索等实现。

不能继续沿用“完全没有导入、多库、备份、WebDAV、语义检索”的旧缺口清单。旧文档中相应描述已经落后于代码：

- [功能 API 入口](../server/library-api.mjs#L270-L325)
- [应用侧功能接线](../src/library/app.js#L1218-L1223)
- [WebDAV 接线](../server/library.mjs#L304-L305)

### 1.2 与 Serpent 的对标结论

| 方向 | AssetVault 当前边界 | Serpent 参考价值与边界 |
| --- | --- | --- |
| 在线获取 | 多站点发现、授权下载、素材包与 3D 工作流是优势 | 媒体直链＋扩展采集；不能当作站点聚合搜索器 |
| 本地存储 | 目录扫描条目与数据库资产仍存在不同处理路径 | 托管／链接双轨，导入预检与冲突决策更完整 |
| 数据生命周期 | 有备份、回收站及删除入口，但边界不统一 | 托管回收站、恢复冲突、缺失重链接、派生任务恢复可借鉴 |
| 同步 | JSON 目录快照，不含原件；复用导入补空语义 | 文件＋部分标注双向交换，但不完整同步合集，且仍有并发窗口 |
| 智能检索 | 已有文字 embedding，不等于视觉相似 | 结构化检索、AI 规划、多模态索引分层可参考 |

Serpent 不是已验证无缺陷的标准实现；本次仅静态审查其相关能力，没有构建、运行或验证检索效果。

## 2. 产品原则与非目标

### 2.1 必须守住的原则

1. 本地优先：离线仍可浏览已有资产、搜索标注、查看来源；未经授权不上传原件或标注。
2. 身份稳定：文件搬家、断盘、重新下载、跨设备迁移，不得无故丢失标签与合集关系。
3. 权限由后端执行：隐藏按钮、来源请求头、访客自填名字都不构成权限边界。
4. 可恢复：删除原件、替换导入、恢复备份、同步删除必须有明确预检和回退机制。
5. 同步诚实：分别显示目录、标注、原件、派生物的同步状态，不把 JSON 上传成功称为完整库已同步。
6. 证据分层：单测通过不能替代宿主、真实 WebDAV、在线站点或视觉验收。

### 2.2 本轮不包含

- 绕过来源授权、付费、DRM 或站点访问限制。
- 因对标而照搬整个 Serpent UI、插件生态或数据库。
- 在未确认库规模前承诺性能数字或工期。
- 静默迁移现有库、删除素材、上传数据或启用云同步。

## 3. 第一阶段：修复清单

### AV-SEC-01｜LAN 自报姓名可冒充高权限成员

- **优先级**：P1，启用 LAN 共享时应优先修复。
- **证据**：静态确认。
- **机制**：统一共享密码验证后，登录者自填 username 写入会话；角色解析再按同名成员授予角色。知道共享密码的访客可以使用已有 owner/editor 名字登录。
- **定位**：[登录处理](../server/lan-sharing.mjs#L129-L157)、[身份解析](../server/library-members.mjs#L119-L131)。
- **修复方向**：展示名与身份解绑。共享密码仅获得访客身份；提升权限必须绑定不可伪造的成员凭据或主机批准的会话／邀请。角色变化和禁用须在服务端生效。
- **验收**：自填主管姓名仍为 viewer；重名不串号；禁用成员不能靠改名恢复权限；既有合法成员迁移路径明确；成员凭据不进入日志。

### AV-SEC-02｜旧写接口绕过角色授权

- **优先级**：P1。
- **证据**：静态确认。
- **机制**：旧状态写入与物理删除不经过新 libraryApi 的统一角色授权。访客持共享会话即可触达部分旧写操作。
- **定位**：[旧状态路由](../server/library.mjs#L346-L362)、[物理删除路由](../server/library.mjs#L765-L820)。
- **修复方向**：盘点所有写路由，路由分发前统一鉴权；主机专属操作另外限制。不能仅给两个已发现接口补孤立判断。x-sfx-local 等标记只能参与请求防护，不能充当成员权限。
- **验收**：viewer 对所有写入口得到拒绝且磁盘／DB／任务均不变化；editor 仅执行授权动作；主机功能保持可用；旧客户端不再能绕过。

### AV-DATA-01｜恢复前备份裁掉恢复目标

- **优先级**：P1。
- **证据**：已复现。
- **机制**：restore 先调用 runNow 创建安全备份，runNow 自动 prune。备份数已满时，最老的被选备份可能先遭删除，再恢复报 ENOENT。keep=1 可稳定触发。
- **定位**：[保留清理](../server/library-backup.mjs#L89-L99)、[创建备份](../server/library-backup.mjs#L106-L144)、[恢复](../server/library-backup.mjs#L159-L192)。
- **修复方向**：恢复期间 pin 目标，安全备份与清理分离；验证目标完整后再替换，成功或明确回滚后才按策略清理。评估恢复操作与备份任务的并发互斥。
- **验收**：keep=1、达到上限恢复最老项、目标损坏、备份失败、复制失败均覆盖；恢复目标不能被提前删除；失败不损坏现库；安全副本可回退。

### AV-SEC-03｜代理跨域重定向携带原站 Cookie

- **优先级**：P1。
- **证据**：静态确认；限代理分支。
- **机制**：初始请求生成 Cookie 后，代理重定向沿用同一 headers，跨域时没有剥离或重新计算敏感凭据。
- **定位**：[重定向](../server/public-http.mjs#L263-L268)、[初始 Cookie 选择](../server/public-http.mjs#L291-L302)。
- **修复方向**：每一跳独立校验 URL 与凭据作用域；跨 origin 清理 Cookie／Authorization 等敏感头，再按目标域重新从 jar 选取；明确 HTTPS 降级规则。
- **验收**：同域、跨子域、跨域、多跳、HTTPS→HTTP 的行为明确；第三方接收不到原站凭据。测试只使用虚构凭据。

### AV-SEC-04｜代理 TLS 默认不校验且错误时降级

- **优先级**：P1。
- **证据**：静态确认。
- **机制**：SFX_PROXY_VERIFY 未设置时传入 false；显式开启后遇证书错误仍再次以 false 建连。
- **定位**：[隧道 TLS](../server/public-http.mjs#L203-L210)。
- **修复方向**：默认严格校验，证书错误明确失败；如需企业代理 CA，提供显式可信 CA 配置，不以静默关闭验证替代。
- **验收**：有效证书通过；过期、不受信任、域名不匹配均失败；严格模式不能自动降级；错误信息不泄漏凭据。

### AV-DATA-02｜replace 导入残留旧回收站和合集

- **优先级**：P2，完成前不应宣传为完整整库替换。
- **证据**：已复现。
- **机制**：replace 调用 readCatalogUids() 默认只清 active；旧 trashed 与旧合集未同步清理。
- **定位**：[replace 分支](../server/library-portable.mjs#L153-L161)、[默认查询范围](../server/library-db.mjs#L486-L488)、[合集导入](../server/library-portable.mjs#L192-L209)。
- **修复方向**：先定义 replace 的完整域范围；采用可回退的事务或暂存库切换，避免分批中断留下半库。元数据替换不能默认删除磁盘原件。
- **验收**：旧 active／trashed／合集及成员关系按契约清理；快照外数据不残留；校验失败零变更；中途失败可回滚；原件不被静默删除。

### AV-SEARCH-01｜最新用户备注没有进入向量索引

- **优先级**：P2。
- **证据**：已复现。
- **机制**：build 从 assets.payload 取 note，而用户域更新写入独立 note 列。保存新备注后 build 仍跳过旧 hash。
- **定位**：[向量构建](../server/vector-index.mjs#L95-L119)、[文本字段](../server/vector-index.mjs#L21-L35)、[用户域写入](../server/library-db.mjs#L759-L780)。
- **修复方向**：从统一的最新有效资产视图构建文本；定义标签／备注变化的失效机制。状态应统计真正待重建资产，不仅计算资产数减向量数。
- **验收**：通过真实业务写入口修改／清空备注及标签，只有受影响项重建；新文本可检索；旧文本不继续作为当前内容；状态准确。
- **性能注意**：当前 build 虽分批调用模型，但先全量读取 active payload、标签和 hash；应改为分页扫描，不能据注释宣称已做到有界内存。

### AV-SYNC-01｜快照交换不具备完整双向同步语义

- **优先级**：P2；在承诺多设备同步前完成。
- **证据**：静态确认。
- **机制**：WebDAV 复用 merge 导入，已存在 UID 的标注保留本机，评分／备注／收藏仅补空；取消收藏、删标签、修改已有评分无法可靠传播。快照与版本元数据分两次无条件 PUT，无远端条件写保护。
- **定位**：[同步流程](../server/webdav-sync.mjs#L155-L187)、[补空语义](../server/library-db.mjs#L750-L780)、[用户种子映射](../server/library-portable.mjs#L180-L189)。
- **修复方向**：将“导入合并”与“同步合并”分离；设计字段版本、删除墓碑、冲突副本／用户裁决；以远端条件提交避免覆盖，原件采用流式传输。
- **验收**：双设备并发新增不丢；评分修改、标签删除、收藏取消能传播；中断不产生成功假象；远端不支持条件写时明确降级，不声称强一致。

### AV-META-01｜默认导出时间字段是函数

- **优先级**：P3。
- **证据**：临时库确认 exportLibrary 默认 exportedAt 类型为 function，JSON 序列化后字段缺失。
- **定位**：[导出](../server/library-portable.mjs#L60-L85)。
- **修复方向**：统一 now 的接口并输出数值；同时把导出时间从同步内容 hash 排除，否则修正时间后可能引入无内容变化也上传的问题。
- **验收**：默认与注入时钟均输出正确数值；未改业务内容连续同步为 noop。

## 4. 第二阶段：统一资产底座

### 4.1 目标数据模型（建议，不是现有 schema）

| 实体 | 职责 |
| --- | --- |
| Asset | 稳定资产 ID、名称、类型、来源关系、生命周期状态 |
| FileLocation | 一项或多项原件位置、托管／链接、设备、在线状态、指纹 |
| SourceRecord | 来源 URL、平台 ID、作者、许可及获取时间、授权边界 |
| Annotation | 人工／AI 标签、备注、评分、收藏，区分来源和字段版本 |
| CollectionMembership | 普通合集关系；智能合集保存查询条件 |
| Derivative | 缩略图、代理视频、波形、预览模型、向量的任务与版本 |
| SyncRecord | 设备基线、字段版本、墓碑、传输及冲突状态 |

同一内容是否共享一个资产 ID 必须显式决策：不同来源或用途可以保留多个逻辑资产，通过内容指纹关联，不能把“内容相同”直接等同于“可以合并并删除”。

### 4.2 导入与去重

流程：选择来源 → 预检 → 冲突决策 → 暂存／校验 → 提交入库 → 派生任务 → 结果报告。

要求：

- 区分同内容重复、同名异内容、已入库、缺失文件、离线目录。
- 提供跳过、保留两份、替换、链接等适用选项；批量规则可预览。
- 精确去重依赖内容哈希；同名同大小仅用于“疑似”，不可自动删除。
- 大文件哈希与复制可取消、可恢复；失败不留下假成功条目。
- Eagle 导入验证标签、评分、备注、合集、原件路径及再次导入策略，不先承诺无损。

### 4.3 托管与链接

- 托管：应用负责复制、命名冲突、回收、恢复和迁移。
- 链接：默认不移动或改写原件；断盘保留资产及标注；重新定位不生成全新资产身份。
- 明确区分从库移除、移除根目录、移至应用回收区、永久删除原件。
- 路径重连先预览，允许指纹消歧，拒绝错误一物多绑。

现有离线根状态与重新定位应复用：[根目录管理](../server/import-roots.mjs#L50-L83)。已有监听也应复用，不重复造第二套 watcher：[扫描缓存监听](../server/scan-cache.mjs#L74-L87)。

## 5. 第三阶段：可靠本地＋在线协同

### 5.1 状态可见

把以下维度分别展示，不能强行挤成互斥的单一状态：

- 来源：仅在线记录／已收藏／授权已失效。
- 原件：未下载／下载中／本机可用／外盘离线／缺失。
- 整理：待整理／已有标注／加入合集。
- 同步：仅元数据／原件待传／已校验／冲突／失败。

在线结果能直接识别已有资产，避免重复下载；下载完成自动关联原资产，来源与许可随记录保留。

### 5.2 分层同步契约

| 层 | 首要策略 |
| --- | --- |
| 目录与标注 | 版本化、可合并、可审计，明确删除语义 |
| 原件 | 用户主动选择范围、流式／断点传输、落地后内容校验 |
| 派生物 | 按需缓存或重建，不默认视作不可丢的原件 |
| 本机配置／凭据 | 不随普通资产快照上传，确需跨端另行授权设计 |

推荐提交步骤：读取远端基线 → 计算三方差异 → 上传暂存对象 → 校验 → 条件提交新 manifest → 更新本地基线。具体协议在实现前单独评审，不能仅给原有 PUT 加重试就称并发安全。

Serpent 对标注意：其[同步元数据范围](../../Serpent/src/worker/sync/sync-metadata.ts#L1-L28)不含完整合集；[manifest 提交](../../Serpent/src/worker/sync/sync-engine.ts#L252-L262)也存在无条件写窗口，不直接照抄。

### 5.3 在线采集与创作交付

- 浏览器采集利用用户已授权登录态，明确目标目录／合集与来源信息。
- 下载任务按来源配置并发、限速、取消和重试；授权过期明确提示，不静默循环。
- 对模型、材质、贴图、预览、许可文件保持包级关系。
- 保留现有 Blender 交付优势，按能力增加其他目标，不为对标一次性接入所有工具。

## 6. 第四阶段：搜索与多媒体质量

1. 统一普通目录、链接资产、在线收藏的结构化查询入口，支持保存为智能合集。
2. 文本检索、AI 查询规划、文字向量、多模态向量分别命名和配置。
3. 视觉检索先以图像与 3D 预览图试点，评估本地模型、远程模型的隐私与资源成本。
4. 派生任务有 queued／running／ready／failed／unsupported 等明确状态；依赖缺失与源损坏分开处理。
5. 同格式“可识别”“有缩略图”“可交互预览”“可编辑”分别列支持矩阵，不合并宣称。

## 7. 实施里程碑与停止条件

| 里程碑 | 内容 | 放行条件 |
| --- | --- | --- |
| M0 安全与恢复 | SEC-01～04、DATA-01 | 权限矩阵测试通过；代理敏感头与 TLS 测试通过；满额恢复不丢目标 |
| M1 现有功能纠偏 | DATA-02、SEARCH-01、META-01 | replace 域范围明确；真实标注更新驱动索引；导出时间与同步 hash 正确 |
| M2 本地底座 | 资产身份、导入预检、托管／链接、可恢复删除 | 导入→移动→断盘→重连→删除→恢复后身份和标注保持 |
| M3 跨端协同 | SYNC-01、原件传输、冲突处理 | 双端并发、断网、中断、远端变更、删除恢复场景通过 |
| M4 差异化体验 | 来源链、智能合集、多模态、创作交付 | 代表性用户素材集验收，隐私与资源成本可解释 |

不按固定天数承诺。先确认实际资产规模、支持宿主、数据根与迁移兼容范围，再拆任务和估期。

## 8. 测试与迁移要求

### 8.1 已执行的证据

- 未经用户授权，不自动上传、物理去重或删除原件。
